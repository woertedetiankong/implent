# implent

用 AI 写代码时，让 AI 接得上，让人看得懂。

仓库里有两个配合使用的插件，Claude Code 和 Codex 都能用：

| 插件 | 给谁用 | 做什么 |
|---|---|---|
| `bearings` | 人 | 把项目画成一张导览图：分成哪几块、每块怎么工作、块和块怎么连、最近的改动落在哪 |
| `implementation-journal` | AI | 跨会话的记忆：每件事一个文件，记下代码里看不出来的决定和下一步，让下一个会话接着干 |

两个都只做记录和展示。它们不规定 AI 怎么写代码，不拦任何改动。

它们在“任务”上接头：

- AI 每次停下来之前，用 `implementation-journal` 把这件事的现状写进它的记录。记录是写给下一个 AI 的，但开头有几行专门写给你：这件事叫什么、做到哪了、有哪些在等你拿主意；做完一步以后，还有做成了什么、你可以怎么试、流程图上哪几个框变了。
- `bearings` 把这几行画到导览图上的“正在做的事”里，并量出这件事动过哪几块；做完的那一步画成一页图文：三段话、亮起的房间、标出变化的流程图。做完的任务一直留在地图上：头一个月在“最近做完的事”里，之后收进“更早做完的事”。你不用去翻那些给 AI 看的文件。
- 做完的需求过一阵又被改了，地图会量出来：它动过的文件后来又被改了几次，并提醒说明可能已经过时。让 AI 接着改同一件事时，卡片会回到“正在做的事”，标着“重新打开”，再做完就是“第 2 次做完”；这段经过是从那份记录的提交历史里读出来的。
- 你看完，开一个新窗口说“继续做某某”，`implementation-journal` 就按这个名字找到那份记录，接着干。
- 收尾时 AI 还会顺手更新 `bearings` 的清单和流程图。

两个可以各自单独安装，只是单装一个时，上面这条线就接不上。

> `bearings` 现在是原型，在三个真实项目上试过（一个网站、两个大型开源项目），名字也是临时的。`implementation-journal` 的上一个版本在十几个项目里用过；现在这个一件事一个文件的写法是 2026-11-14 改的，只在试验里跑过。

# bearings：给人看的导览图

## 你会看到什么

说一句“看看项目”，浏览器里打开一页导览图。顶上两个标签，各回答一个问题：

| 标签 | 回答什么 | 从哪来 |
|---|---|---|
| 怎么运转 | 整个项目怎么运转：一张框架图，点一个方框，进到它里面。图下面是“跟着一件事走”，选一件事，画出它从头到尾经过哪几块 | 清单里写下的描述 |
| 改动落在哪 | 全部的块在一张平面图上，有改动的亮着，标出是哪个窗口在动 | 清单、提交记录和未提交的改动 |

哪一块用到哪一块是从代码里量出来的，不单独成图：图上代码里量不到的连线画成虚线，每一块的详情里列着“它用到”和“用到它的”。

隔了一阵再回来看的人，先看框架图下面的**这段时间的变化**：最近 7 天、30 天或 90 天里新增和去掉了哪些块、哪些图重画了、每件事是做完了还是重新打开了、哪几块改得最多，以及哪些说明和图已经被代码甩在后面。这些都是量出来的，不是 AI 写的总结；页面会记住你上次打开的时间，自动选能盖住它的那一档。

点开任何一块，下面是它的详情：

- **进来什么，出去什么**：外面的图上连到这一块的每一条线，谁传进来什么、它传出去什么。
- **流程图**：这一块是怎么工作的，谁把什么传给谁。被打开的这一块画成一片色块，它里面的方框在色块上；它连着的别的方框站在色块外面，入口在左，出口在右，点一下就走过去。

框架图是一层套一层的：整个项目里是几个区，区里是块，块里是小房间，小房间里是步骤。上一层画了一条线连到某个方框，打开这个方框，里面必须找得到这条线的另一头；对不上的地方，页面用虚线标出来，体检也会报告。
- **里面有什么**：大的块里还有小房间，可以继续点进去。别人写的代码（第三方库）画成虚线框，不算进项目自己的文件数。
- **它用到 / 用到它的**：这一块引用了哪些块，又被哪些块引用，各有多少个文件。
- **规矩和“要小心”**：项目自己文档里写过的规矩，以及涉及钱、登录、数据、线上配置的块。

页面上还有：

- **亮灯**：还没提交的改动落在哪几个房间。改动的文件如果不属于清单里的任何一块，会单独列成“未归类”，旁边写着让 AI 把它们补进清单的那句话。
- **谁在动哪里**：每个在这个项目里干活的 Claude Code 或 Codex 窗口一行：它在干活、在等你回话还是停住了，最近一次让它做什么，动了哪几块，提交过几次。亮灯的房间上标着是哪几个窗口在动；两个窗口撞车的地方单独列在最上面。点一行，只看这个窗口。
- **脚印**：最近每次提交踩到了哪几块。
- **正在做的事**：装了 `implementation-journal` 时，每个没做完的任务一张卡片：叫什么、做到哪了、有几件事在等你。点开它，地图上亮起这件事动过的房间，下面写着等你的事和接着做要说的那句话。AI 写了的话，还有刚做完的一步：做成了什么、怎么试、还没做的，以及这一步在流程图上新增、改了、去掉了哪几个框。做完的任务标着“做完了”，一个月后收进“更早做完的事”，不会消失；它动过的文件后来又被改过的，标着“之后又改过”。

页面由脚本根据一份清单、git 历史、代码里的引用语句和本机的会话记录生成，生成时没有任何一句是 AI 现写的。

## 安装

需要 Python 3 和 git，不需要其他依赖。

### Claude Code

在 Claude Code 里输入：

```text
/plugin marketplace add woertedetiankong/implent
/plugin install bearings@implent
/plugin install implementation-journal@implent
```

以后更新：

```text
/plugin marketplace update implent
```

### Codex

把技能文件夹复制过去（`bearings` 在 Codex 里还没有实际验证过）：

```sh
git clone https://github.com/woertedetiankong/implent.git
cp -R implent/bearings/skills/bearings ~/.codex/skills/
cp -R implent/implementation-journal/skills/implementation-journal ~/.codex/skills/
```

## 使用 bearings

在你的项目里对 AI 说：

- “给这个项目建一份部分清单”：AI 读一遍仓库，写出 `docs/parts.md`，再请你改名字。第一遍只画大块的流程图，小房间只列出名单。这一遍 AI 会读代码再画，不看文件名猜，所以大项目上不便宜：在一个 6000 个文件的项目上实测约 10 分钟、10 美元。
- “给‘运行循环’画流程图”：想看哪个小房间内部怎么工作，就点名让它画。页面上每个还没画的房间下面都写着这句话。
- “清单还准吗”：做一次体检，见下面。
- “这几块是怎么连起来的”：列出从代码里量出来的引用关系。
- “看看项目”或“打开项目地图”：生成并打开导览图。
- “刚才动了哪几块”：列出未提交的改动落在哪些部分。
- “现在在做哪些事”“有什么在等我”：列出没做完的任务和每件事等你做什么。
- “给‘网站语音助手’写一份做完后的说明”：让 AI 补上做成了什么、怎么试和流程图上的变化，导览图上就能看到。
- “继续做‘网站语音助手’”：按导览图上的名字接着做那个任务。

在 Claude Code 里也可以直接输入 `/bearings:map` 打开导览图。

不装插件也能直接运行脚本。克隆仓库后，在你的项目目录里：

```sh
B=/path/to/implent/bearings/skills/bearings/scripts/bearings.py
python3 $B web --open            # 生成并打开导览图
python3 $B parts                 # 列出各部分，检查有没有漏掉的文件
python3 $B links                 # 哪一块用到哪一块，从代码里量
python3 $B doctor                # 体检：清单过时了没有，有没有写错
python3 $B check                 # 未提交的改动落在哪几块
python3 $B check --commit <提交>  # 某一次提交落在哪几块
python3 $B tasks                 # 正在做的事：做到哪了，在等你什么，动过哪几块
```

导览图写在仓库的 `.git/bearings/map.html`，不会进入版本历史。

没有数据库：清单和任务记录是仓库里的普通文件，其余的每次从 git 里现量，页面一两秒整个重画，不调用 AI，所以可以随时重新生成。清单还没提交过的项目，脚本会在页面旁边（`.git/bearings/lists/`）留下带日期的清单副本，用来对比“这段时间变了什么”。

## 体检

清单是人和 AI 写下来的描述，代码改了它不会自己跟着变。`doctor` 命令拿清单和代码对一遍，报告：

- 清单里的路径已经对不上任何文件（代码挪过位置）。
- 流程图里的方框名字差一点就是另一块的名字（多半写错了，所以点不过去）。
- 大块的流程图没有用自己的小房间当方框（可能和某个小房间画重了）。
- 图上画了、代码里量不到的连接（走网络的属于正常）。
- 流程图画完之后，这一块的代码又改了很多次。
- 层和层对不上：有方框不在装着它的那张图上；上一层画了线，打开方框后里面没接上；方框自己的图连到了外面，外面却没有图画这条线；主线上的一步在框架图里找不到。
- 箭头没写传的是什么；一张图断成了几截；箭头上写的代码名字在代码里已经找不到。

体检只报告，不拦任何事。它查得出两层对不上，查不出哪一层是对的：那要回去读代码。

页面上每张流程图下面也会写“画于哪天，之后改了几次”，改得多的标成“可能已经过时”。

体检只报告，不拦任何操作。它查得出清单过时和写错，查不出一张流程图画得对不对，那只能靠人看，或者让 AI 重新读代码重画。

## 同时开多个窗口

窗口一多，就说不清哪个窗口在做什么、哪个停下来在等你、哪两个改到了一起。git 只知道哪些文件变了，不知道是谁改的。`bearings` 会去读 Claude Code 和 Codex 留在本机的会话记录，把每个窗口放到项目上：

- **最近一天在这个项目里干过活的窗口，每个一行。** 没有未提交改动的也算（在读代码、在计划，或者已经提交了）。每个窗口有一个字母和一个名字：名字优先用它正在写的任务，没有就用会话标题或第一句话。
- **它现在怎样。** 在干活；停下来等你回话；停住了（在一步操作中间停了一阵，可能在等你批准，也可能在跑一条很久的命令）；没在动。
- **最近一次让它做什么**，用的是你当时打的那句话。
- **它动了什么。** 未提交的文件落在哪几块；它提交过几次。
- **撞车。** 两个窗口改了同一个文件；同一个文件在两个工作区里都改了（合并时会冲突）；两个窗口在改同一块。清单本身不算，因为每个窗口都要更新自己那几行。

这和市面上的会话管理工具不是一回事：那些工具管的是会话本身（启动、切换、看输出），这里只回答一个问题，这几个窗口各自把项目改成了什么样、我该先看哪里。它只看不管。

命令行里是 `bearings.py windows`；`check` 命令在有多个窗口时也会多出一段“按窗口分”。用了 git worktree 时，导览图把所有工作区的未提交改动画在同一栋楼里，并标明在哪个工作区。

它怎么判断：用编辑工具改的文件，记录里写着是哪个窗口，这部分是确定的。用命令改的文件，看它的修改时间落在哪个窗口的命令运行期间，只有一个窗口对得上时才算；提交也是这样对到窗口上的，这部分是推断。两样都对不上的，显示为“没记到是哪个窗口”。窗口的状态是生成页面那一刻读的，想知道它现在是不是还在干活，要重新生成。

会话记录只在本机读，不会发到任何地方。窗口的名字和你最近打给它的那句话会写进生成的页面，把页面发给别人之前留意一下。不想读会话记录，加 `--no-windows`。

# implementation-journal：给 AI 的记忆

新开的会话不记得上一个会话的事。其中大部分它自己查得到：代码说明做了什么，git 说明改过什么、撤回过什么。查不到的是只在对话里说过的东西：你做的决定、外部的限制、需求没说清时 AI 做的猜测、还在等你回答的问题。这个技能只记这些。

每件事一个文件，放在项目的 `docs/tasks/<日期>-<名字>.md`，三节，三四百词：

- **给人看的**（`## For People`）：这件事叫什么、现在怎样、哪些事在等你，以及做完的一步做成了什么、怎么试、流程图上变了哪几个框。导览图只显示这一节。
- **定过的事**（`## Decided`）：只记代码和 git 里看不出来的。做了什么、改了哪些文件不记。
- **下一步**（`## Next`）：下一个会话按顺序做什么，以及用哪条命令确认现状。

它还会在收尾时把已经过时的 README 和文档改对，并在项目有 `docs/parts.md` 时更新导览图的清单。

**为什么只有一个文件。** 2026 年 11 月 14 日之前，每件事是一个文件夹、四份文件（任务书、决定日志、交接、下次开场白）。那天做了两次对照试验：

| | 小项目，自己搭的 | 难项目，pydantic-ai 的一个真实改动 |
|---|---|---|
| 四个文件 | 8 项隐藏测试全过 | 行为测试过 137 项，17 分钟 |
| 一个文件 | 8 项全过 | 137 项，同一批，12 分钟 |
| 没有记录 | 过 6 项，丢的正是哪都没写的两条决定 | 137 项，25 分钟 |

一个文件不输给四个文件；没有记录时，代码和 git 里有的东西 AI 都能自己找回来，丢的只是没写下来的决定，另外要多花一倍时间重新读代码。每组只跑了一两次，只能说明大的差别。

**旧项目不用动。** 已经有任务文件夹的项目照旧能读：导览图、开会话时的提示和校验脚本都还认 `handoff.md`。AI 接着做旧任务时继续写在原来的 `handoff.md` 里，新任务才用一个文件的写法。

**同时开多个窗口。** 每件事的记录是自己的一个文件，没有全仓库共用、会被互相覆盖的文件。开新会话时：只有一件事在进行，就自动带上它的记录；有几件在进行，就列出来，由你说这个窗口做哪一件。各窗口只写自己那件事的记录，改共用文档（README、`docs/parts.md`）时只改自己那几行。记录标成 Complete 之后，它就不再出现在列表里。

**回头改做完的事。** 让 AI 改一件已经做完的需求时，它在原来的记录里接着写，把状态改回 Open，不另开一份。改动很小的话，只修正记录里被它改得不对的那几行。

在 Claude Code 里，插件带两个钩子：开新会话时告诉 AI 有哪些事在进行；改完记录后自动校验格式。Codex 没有钩子，靠技能说明里的步骤完成同样的事。

校验脚本可以手动运行：

```sh
python3 /path/to/implent/implementation-journal/skills/implementation-journal/scripts/validate_journal.py docs/tasks
```

一次就做完、没有什么需要记住的小改动不需要用它。

## 已知的不足

- 导览图上的“正在做的事”是新加的：在测试仓库和一个真实项目的任务记录副本上试过，那几行“给人看的话”是手写进副本的。AI 会不会每次停下来都把这几行写好、写得让不会编程的人看懂，还没有在真实使用中验证。
- 一件事动过哪几块，是从它的记录里提到的提交、和它的记录一起提交的改动、以及正在写它的窗口里量出来的。记录和代码分开提交、记录里又没写提交编号时，量不到。

- 多窗口并行的支持是新加的，钩子和校验都测过，但还没有在真实的并行开发里用过。
- `bearings` 按窗口分开改动，靠的是 Claude Code 和 Codex 的本机会话记录。这两种记录的格式没有公开文档，工具升级后可能读不出来；读不出来时页面退回到不分窗口的样子，不会出错。
- 用命令改的文件是按时间推断的，偶尔会认错或认不出。只读最近 14 天的会话记录。在别的电脑或云端跑的会话看不到。
- 按窗口分开这件事，在一个测试仓库和一个真实项目的历史记录上验证过，还没有在真正同时开着几个窗口的开发中用过。
- 谁用到谁只量得到 Python、JavaScript/TypeScript、Go 的引用语句和 C/C++ 的 `#include`。Rust、Swift、MATLAB/Simulink 等语言，以及走网络的连接，量不到。
- 量连接宁可少算，不算错。Python 里，一个名字在仓库里有好几处能对上，或者引用的是另一个文件夹里的单个脚本（那个文件夹没有 `__init__.py`，不是引用方的上级目录，引用方也没有自己用 `sys.path` 把它加进来）时，不算连接：光看引用语句，分不清它指的是哪个文件，还是标准库、第三方库里的同名模块。TypeScript 的路径别名只对写着它的那个 `tsconfig` 所在文件夹里的文件生效，通过 `extends` 从别的文件夹继承来的别名量不到。
- 一个区还没有画图时，页面会用量出来的连接临时画一张“谁用到谁”。它的上下分层是按“用别人多还是被别人用多”算的，是一种概括，不是严格的架构分层。
- 流程图要靠 AI 在改动后顺手更新。它会不会一直这样做，还没有在长期使用中验证过。
- 脚印旁边显示的是提交说明原文，不会编程的人可能看不懂。
- 在两个大型开源项目上，全新的会话只凭一句话就建出了清单（约 7 到 8 分钟）。但 AI 画的流程图只抽查过几张，没有逐张核对。
- `/bearings:map` 命令还没有在真实会话里运行过。
- 手机宽度和深色模式没有充分检查。
