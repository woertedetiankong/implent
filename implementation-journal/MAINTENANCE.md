# Maintaining This Plugin

Guidance for editing the plugin itself. Nothing in this file is loaded at runtime; do not reference it from SKILL.md.

- Layout: the plugin root holds `.claude-plugin/plugin.json` and `hooks/`; the skill lives in `skills/implementation-journal/` with its `references/`, `scripts/` and `agents/`. The repo root's `.claude-plugin/marketplace.json` lists the plugin. Marketplace installs are copied to a cache, so everything the plugin uses must stay inside this folder; `../` paths do not load. For Codex, copy `skills/implementation-journal/` on its own.
- When changing SKILL.md or the references, validate with isolated subagents or thread forks if the environment supports them. Give each agent a realistic scenario and the skill artifact, not your expected answer. If no subagent facility is available, skip this step and note the limitation.
- Each rule lives in exactly one place: creation conditions and triggers in SKILL.md; formats, field definitions, and deep guidance in `references/`. Before adding text, search the other files for restatements of the same rule and consolidate instead of duplicating.
- Several sessions may work in one repo at once. Nothing the skill writes may be a single repo-wide file that each session rewrites: that is why the new-session entry lives in each dossier (`next-session.md`) and why there is no index. `hooks/session_start.py` derives the list of open tasks by scanning dossiers instead of reading a shared file. Keep it that way when adding features; the repo-level `docs/tasks/NEXT-SESSION.md` is read only for repos that have not moved yet.
- The document set is deliberately small: task brief, implementation log, handoff, new-session entry. A milestone report for people, a task index, and wiki templates were removed on 2026-11-11 because the reports went unread, the index went stale, and no repo using the skill had a wiki. The `bearings` plugin in this repo is the view for people. Before adding a new kind of file, check that someone will read it.
- `skills/implementation-journal/agents/openai.yaml` is metadata for a non-Claude harness; Claude Code ignores it. Keep it only while the skill is used with that harness.
- `hooks/hooks.json` registers the two hook scripts through the plugin. `hooks/post-edit-validate.sh` finds the validator at `skills/implementation-journal/scripts/validate_journal.py` relative to the plugin root; keep that path and the `docs/tasks/` pattern in sync with SKILL.md. hooks/README.md keeps a manual settings.json snippet only for setups where the plugin is not loaded; never both, or every hook runs twice. Do not add a `paths:` frontmatter field to SKILL.md: it limits auto-loading to sessions that touch matching files, which would stop the skill triggering before a dossier exists.
- `scripts/validate_journal.py` mechanically mirrors rules that live in SKILL.md and `references/` (handoff frontmatter and sections, handoff read budget, restart-verify shape, relative-date bans, log entry format, session-entry fields and its pointer to the handoff beside it, template placeholders). When editing those rules, update the script's checks in the same change, and rerun it against one known-good and one deliberately broken fixture dossier before shipping.
